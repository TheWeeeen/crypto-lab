# crypto-lab — проверялка гипотез на крипторынке

Тренажёр для проверки торговых правил на исторических данных.
**Не торгует, к бирже не подключается, денег не касается** — только скачивает публичные свечи
и считает, что было бы, если бы правило применялось на них.

Две версии:

* **веб** — `server.py` + `web/` — график со свечами, рисование уровней/трендлайнов/каналов/Фибоначчи
  и проверка нарисованного в один клик;
* **консольная** — `cli.py` — то же самое для агента и скриптов, вывод в JSON.

Только стандартная библиотека Python 3.11+ (без numpy/pandas) и чистый canvas в браузере
(без внешних JS-библиотек). Данные — публичное API Binance (spot + fapi), кэш на диск.

---

## Как запустить

```bash
# веб
LAB_TOKEN=<свой-код> python3 server.py --host 127.0.0.1 --port 8097

# консоль
python3 cli.py scan  --symbol BTCUSDT --limit 1000
python3 cli.py bt    --symbol BTCUSDT --strategy ma_cross --fast 20 --slow 50
python3 cli.py levels --symbol BTCUSDT --top 5 --trials 40
```

Скопируй `.env.example` в `.env` и задай свой `LAB_TOKEN` — это код доступа к панели,
он спрашивается в браузере один раз.

## Что внутри

| файл | зачем |
|---|---|
| `lab/data.py` | свечи Binance с кэшем, список торгуемых пар, фандинг |
| `lab/metrics.py` | доходность, CAGR, волатильность, Sharpe, макс. просадка, комиссии |
| `lab/engine.py` | движок бэктеста; **решение по закрытию бара i действует с бара i+1** (защита от look-ahead) |
| `lab/strategies.py` | 15 стратегий: MA, RSI, моментум, каналы, сетка, тейки, стопы + 4 «рисовальных» |
| `lab/levels.py` | автодетекция уровней/трендлайнов/фигур + статистика касаний, отскоков, пробоев |
| `lab/robust.py` | тест на случайность: сколько случайных правил дали результат не хуже |
| `cli.py` | консольный интерфейс |
| `server.py` | HTTP-API + отдача веба |
| `web/` | интерфейс: canvas-график, рисование, панели, таблицы |
| `news_pump_test.py` | проверка «новость → памп» на минутных свечах |
| `listing_collect.py`, `listing_test.py`, `listing_curve.py` | сбор и проверка листингов Binance |
| `watcher.py` | слежение за всплесками и новыми анонсами Binance (не торгует) |

### Стратегии

Обычные: `ma_cross`, `ma_cross_50_200`, `price_vs_ma200`, `momentum_30`, `momentum_90`,
`rsi`, `donchian`, `bollinger`, `grid`, `fib_618`, `buy_hold`.

«Рисовальные» (проверяются из интерфейса по нарисованному объекту):

* `level_breakout` — горизонтальный уровень: пробой вверх (лонг выше уровня) или покупка от уровня (отскок);
* `trendline` — наклонная линия: пробой вверх или вниз;
* `range_trade` — прямоугольник: торговля внутри канала (покупка у низа, продажа у верха);
* `fib_618` — откат к 61,8% по последним N барам.

### Риск-правила

Стоп-лосс, тейк-профит, трейлинг-стоп — задаются в процентах и применяются внутри бара
(сначала стоп, потом тейк — консервативное допущение).

## Что показывает и почему этому можно верить

* **Сравнение с «купил и держу»** — главный ориентир. Правило, которое проигрывает удержанию
  на растущем рынке, эджа не имеет.
* **Комиссии и проскальзывание** считаются на каждую сделку (по умолчанию 0,1% + 0,05%).
  При 365 сделках в год это ~73% капитала — большинство «активных» стратегий убивает именно это.
* **Тест на случайность** (`robust`): генерируются сотни случайных правил с той же частотой входов;
  если проверяемое правило в середине этого распределения — оно ничего не предсказывает.
* **p-value у уровней**: сравнивается доля удержаний уровня с долей удержаний при случайном блуждании.
  p > 0,05 = «уровень ничем не отличается от случайной линии».

## Чего эта штука не делает

* не торгует и не подключается к бирже с ключами;
* не обещает доходность: результат на истории — это проверка гипотезы, а не прогноз;
* не учитывает новости, ликвидность и проскальзывание на больших объёмах.

## Результаты проверок

### Рисование на графике (BTC, 1000 дней)

* автонайденные уровни: удержание против случайной линии даёт p = 0,82–1,00 — уровни не отличаются от случайных;
* фигуры (39 найдено): средний ход +2,3% против базовых +2,0% — превышение 0,3 п.п., то есть шум;
* канал 60 000–90 000: +178% против +84,5% удержания — но границы выбраны по уже прошедшему графику, это подгонка.

Вывод: рисование не даёт эджа, оно даёт ощущение контроля.

### Новости и «памп» (`news_pump_test.py`, 1m за 180 дней, BTC/ETH/SOL/DOGE)

Механика «Маск написал твит → что-то выросло → ловим» проверена без новостной ленты — через
покупку после свечи с ростом и объёмом выше среднего в 2 раза. Вход по открытию следующего бара,
комиссия 0,1% × 2.

* DOGE, спайк ≥0,5%, 263 случая: держим 1м −0,20%, 5м −0,17%, 60м −0,23%. Базовая линия (случайные бары) — те же −0,20%.
* DOGE, спайк ≥1%, 31 случай: 1м −0,46%, 5м −0,57%.
* Шорт против спайка — тоже минус на всех активах.
* **Доля часового хода, уже находящаяся внутри свечи-спайка: 40–48% при пороге 0,5% и 64–94% при пороге 1–2%.**

Вывод: к моменту, когда бот увидел движение и отправил ордер, большая часть хода уже отработана.
Покупка после спайка не отличается от случайного входа, а комиссия 0,2% за круг делает результат
отрицательным. Чем «новостнее» монета, тем хуже: DOGE — худший из четырёх.

### Листинги Binance (`listing_collect.py` + `listing_curve.py`, 233 листинга)

Листинг — единственная «новость» с открытым API (публичный каталог анонсов Binance, `catalogId=48`,
без ключа) и с известным временем старта торгов. Проверены все: **294 анонса, 233 с доступными
свечами**, первые 1000 пятиминуток каждой монеты.

Анонс всегда идёт впереди торгов: медиана **4,1 ч** (минимум 0,9 ч) — то есть фора есть.

| вход | +5 мин | +1 ч | +24 ч |
|---|---|---|---|
| 0 мин | −0,5% (37% плюс) | −3,8% (21%) | **−9,1%** (25%) |
| 5 мин | −1,1% (31%) | −4,5% (21%) | −9,5% (25%) |
| 15 мин | −0,7% (34%) | −2,8% (24%) | −7,6% (28%) |
| 30 мин | −0,5% (33%) | −1,7% (32%) | −6,2% (29%) |
| 60 мин | −0,2% (42%) | −1,2% (34%) | −6,4% (31%) |

Контроль (те же монеты в обычной торговле спустя недели, 13 980 наблюдений): +5м −0,20%, +1ч −0,23%, +24ч −1,29%.

**Ни один реальный вход не даёт плюса ни на одном горизонте.** Через сутки вход в листинг — −9,1%
против −1,29% у обычной торговли, то есть в 7 раз хуже: покупка листинга — это покупка вершины пампа.

Отдельная ловушка: закрытие первой 5-минутки выше её открытия на +36% медианы. Это цена первой
сделки на пустом стакане — она не исполнима. Считать доход от неё нельзя, только от реально
достижимых цен (закрытий свечей).

### Что автоматизируется по-настоящему

Не торговля, а слежение. `watcher.py` раз в 15 минут проверяет самые ликвидные пары на всплеск цены
(≥2% за 5м / ≥4% за 15м) вместе со всплеском объёма и читает публичный API анонсов Binance.
Повторы отсекаются по номеру свечи. Задача — отдать событие человеку раньше, чем он увидит его
в ленте, а не торговать по нему.

## Данные проверок

* `listings.json` — собранные анонсы листингов с точным временем публикации;
* `listing_curve.json` — посчитанные доходности по каждому листингу и точке входа;
* `listing_test_raw.json` — сырые результаты первого прогона;
* `reports/news_pump_test.json` — отчёт по проверке «новость → памп».

## Ограничения

* результат на истории — проверка гипотезы, а не прогноз доходности;
* проскальзывание на больших объёмах и реальная ликвидность не моделируются;
* на листингах первые секунды недоступны человеку в принципе — колокированные боты быстрее;
* возрастной барьер: KYC крупных бирж — 18+.
